# OFFIRST acceptance evaluator audit

## Scope and status

Audited and hardened `tools/real_image_acceptance/evaluate_acceptance.py` on the investigation branch. Changes are confined to the evaluator, its manifest schema and synthetic evaluator tests. No Flutter/Android production code, model assets, preprocessing implementation, weights or production thresholds changed. Synthetic tests validate software contracts only; no real-image acceptance or clinical performance is implied.

## Findings corrected

1. **Patient leakage:** the old evaluator required patient IDs only for test and did not prevent a pseudonymous patient or sample from crossing validation/test. Both partitions now require patient IDs; each patient and sample is assigned to one partition. Every image hash is unique across distinct sample IDs/partitions while repeated runtime rows for the same sample remain allowed.
2. **External-site protocol:** `--external-site-evaluation` now requires non-empty disjoint validation and test site sets. Ordinary patient-disjoint protocol remains available when explicitly appropriate.
3. **Primary acceptance statistics:** accuracy, sensitivity and specificity gates now use the lower endpoint of patient-clustered percentile bootstrap 95% intervals (0.85, 0.85, 0.80). Point metrics and image-level Wilson intervals remain descriptive. AUROC is supplementary and uses scored gradable fundus images only.
4. **Bootstrap validity:** resampling draws whole patient clusters with replacement, retaining all eligible gradable images/eyes/repeats in a selected cluster. Patients with no gradable fundus rows do not enter DR metric resampling. Draws missing a metric's required class are counted as invalid. An interval is withheld if any requested replicate is invalid or if the bootstrap distribution is degenerate; this avoids conditioning on successful draws and avoids reporting a false zero-width interval at perfect/all-wrong boundaries. Valid replicate counts and patient-cluster count are reported. Percentiles use linear interpolation. This strict rule can make intervals unavailable; that is a fail-closed result.
5. **Abstentions:** an unscored gradable positive is counted as FN and a gradable negative as FP for end-to-end classification metrics. Abstentions do not enter AUROC, which is explicitly reported on scored cases and accompanied by coverage. Failed/abstained images cannot become benign by omission.
6. **Cohort sufficiency:** minimums are checked on both validation and test, and counts report unique patients, positive/negative patients, images, sites, devices, gradable/ungradable images, and eye-status categories. Defaults are engineering floors (30 patients, 15 positive patients, 15 negative patients, 2 sites, 2 devices, 30 gradable images, 1 ungradable image), not power guarantees. A positive/negative patient has at least one gradable image of that label; these counts may overlap for patients with differently labeled eyes. CLI minimums may be raised but cannot be lowered below defaults. A predeclared protocol must still record any raised values.
7. **Eye accounting:** manifest requires `patient_eye_status` (`bilateral`, `unilateral`, `missing_eye_record`, `unknown`) consistently for all rows in a patient. Bilateral status requires OD and OS records across that partition; unilateral requires exactly one documented eye. `missing_eye_record` may include a documented available eye while explicitly marking an expected record absent. Counts are reported; universal bilateral availability is not assumed. Both OD and OS cases must appear in test coverage, without requiring each patient to have both images.
8. **Parity, schema and source evidence:** the locked threshold is checked against every validation and test row. The `>=` boundary is retained. Python/Android parity requires paired, scored, gradable fundus records expected to be scored, with identical tensor hashes and probability deltas <=1e-5; missing a required output fails parity. Both OD and OS must be represented. Non-fundus and ungradable inputs are excluded from probability parity and audited through their correct reject/retake outcomes. Duplicate/unknown columns and extra row values are rejected; classified decisions without probabilities and gradable images without adjudicated severity are rejected. Test acceptance requires `--check-image-hashes` so every referenced image is present and matches its manifest hash.

## Tests

`python -m unittest discover -s tools/real_image_acceptance -p "test_*.py" -v`

Synthetic software tests cover patient/eye leakage and missing IDs, cross-platform metadata mismatch, external-site leakage, duplicate hashes, malformed headers, incorrect locked thresholds, Python/Android parity failure, missing outputs/abstentions, minimum-size override attempts, missing-class bootstrap draws, degenerate intervals, repeated-patient clusters, confidence-bound reporting, and bilateral/unilateral/missing-eye records. They do not validate the model or demonstrate screening accuracy. The evaluator fails closed for incomplete manifests and returns a nonzero result when gates fail.

## Remaining methodological limits

The patient-cluster bootstrap treats sampled patient clusters as independent sampling units and retains within-patient correlation. Site-cluster uncertainty is not estimated; external-site separation does not establish enough independent sites for site-level generalization. Percentile bootstrap intervals are asymptotic and can be unstable with few clusters; floors do not guarantee precision. The evaluator refuses degenerate intervals rather than applying an unvalidated boundary correction. AUROC uncertainty uses valid patient-cluster bootstrap draws, while AUROC point estimates exclude abstentions; end-to-end metrics retain gradable abstentions as errors. File/hash checks do not prove clinical provenance, label adjudication, hidden near-duplicates, protocol lock timing, or physical-device behavior; external review remains necessary.
